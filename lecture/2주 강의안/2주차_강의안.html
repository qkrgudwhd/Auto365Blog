365blog 를 내 계정에 맞추기 · F12로 버튼 위치 뽑기 · 디자인이 바뀌어도 혼자 고치기 · 첫 자동 발행

🎯 오늘의 목표

  • 365blog 소스를 내 계정에 맞게 수정합니다. 내 블로그 주소 · 플랫폼 · AI 열쇠(API 키)를 연결합니다.
  • 브라우저 F12로 버튼 위치를 직접 뽑아냅니다. (버튼 위치 = 셀렉터)
  • 사이트 디자인이 바뀌어도 혼자 고치는 법을 익힙니다.
  • 오늘 끝나면 손에 남는 것: 내 블로그에 글 1개 자동 발행 성공 — 그리고 기록 폴더에 첫 발행 캡처와 셀렉터 메모.

오늘은 네 곳을 한꺼번에 하지 않습니다. 내가 이미 가진 블로그 하나만 성공시킵니다. 나머지 블로그는 같은 방법으로 숙제에서 넓힙니다.

오늘 준비물

  • 내 블로그 1개 (네이버 블로그 · 티스토리 · 구글 블로거 · 워드프레스 중 하나). 이미 쓰는 블로그가 가장 좋습니다. 블로그가 없다면 수업 전에 하나 만들어 두세요.
  • 어느 블로그가 지금 가장 잘 되는지는 수업 전에 별님이 단톡방에 알려 드립니다. 블로그가 여러 개라면 그 블로그로 첫 발행을 합니다.
  • 그 블로그의 아이디와 비밀번호를 내가 알고 있어야 합니다. 2단계 인증을 쓰면 휴대폰을 곁에 두세요.
  • 3기_작업\365blog 폴더 — 위 「수업 전에 해 둘 일」로 풀어 둔 것. 못 풀었으면 받아 둔 압축 파일.
  • 크롬(Chrome) 브라우저. 없으면 클로드에게 「크롬을 설치해 줘」라고 부탁하고, 막히면 단톡방에 알려 주세요.
  • 오늘 올릴 시험 글의 제목 한 줄 (예: 「가을 산책길에서 본 것」).
  • 화면이 두 개면 좋습니다. 하나뿐이면 줌 창과 실습 창을 반씩 나눠 쓰세요.
  • 맥을 쓰시는 분 — F12 연습(2단계)은 똑같이 됩니다. 365blog 실행은 윈도우용 부품(SNS Hub.exe 등)이 있어 맥에서 그대로 돌지 않을 수 있습니다. 수업 전에 단톡방에 맥 사용자라고 알려 주시면 별님이 따로 안내합니다.

클로드에게 하는 말투 — 첫 마디(협업지침 읽히기)는 1주차와 같은 문장을 그대로 씁니다. 그다음부터 이 강의안의 문장은 편한 반말입니다. 클로드에게는 반말로 써도 되고, 1주차처럼 존댓말로 써도 똑같이 알아듣습니다.

오늘의 그림 — 365blog 와 셀렉터

  • 365blog 는 네이버 · 티스토리 · 구글 블로거 · 워드프레스 4곳과 SNS 에 글을 올리는 자동 발행 프로그램입니다.
  • 프로그램이 하는 일은 사람이 하는 일과 똑같습니다. 로그인 → 글쓰기 화면 열기 → 제목·본문 넣기 → 발행 단추 누르기.
  • 프로그램에는 눈이 없습니다. 그래서 단추를 글자로 된 주소로 찾습니다.
  • 이 주소를 셀렉터(selector, 화면 속 단추의 위치 주소)라고 부릅니다.
  • 사이트가 디자인을 바꾸면 주소도 바뀝니다. 그러면 프로그램이 단추를 못 찾고 멈춥니다.
  • 그때 F12로 새 주소를 뽑아 클로드에게 주면 고쳐집니다. 이것이 오늘의 「F12 마스터」입니다.

「천천히」 세 가지 약속 — 오래 쓰는 비결입니다

  1. 발행 단추는 한 번만 누르게 합니다. 마구 누르게 하지 않습니다.
  2. 캡차(사람인지 묻는 문제)는 사람이 직접 풉니다.
  3. 실패해도 같은 것을 바로 다시 돌리지 않습니다. 몰아치면 캡차가 늘고 막힙니다.

두 가지 선 긋기

  • 내 계정만 씁니다. 남의 블로그를 대신 돌려 주지 않습니다.
  • 받은 소스는 수강생 외에게 다시 나눠 주지 않습니다.

네 곳의 차이 — 단추 위치만 다릅니다

네이버 블로그네이버 아이디화면 속 화면(iframe)이 겹쳐 있어요발행 단추 → 설정 창 → 한 번 더 발행
티스토리카카오 계정편집 모드가 기본·마크다운·HTML 세 가지 — 프로그램이 알맞게 바꿔 씁니다「완료」 단추 → 작은 창(카테고리·공개 범위) → 「공개 발행」

화면 이름은 조금 다를 수 있어요. 막히면 화면을 캡처해 클로드에게 보여 주세요.
네 곳 모두 순서는 같습니다(로그인 → 글쓰기 → 제목·본문 → 발행). 그래서 F12 하나로 네 곳을 다 고칠 수 있습니다.

1단계 · 365blog 풀고 클로드에게 읽히기 · 켜기 (수업 전 + 수업 10분)

① 무엇을, 왜

  • 풀기 · 읽히기 · 설치는 수업 전에 집에서 해 둡니다. 압축 풀기와 꾸러미 설치에 시간이 걸려서, 수업 시간에 하면 뒤 단계가 밀립니다. 못 했으면 수업 1단계 시간에 함께 합니다.
  • 켜기는 수업에서 함께 합니다.
  • 365blog 압축 파일을 3기_작업 폴더에 풉니다.
  • 클로드에게 설명서(README.md)와 규칙(절대지침.md)을 먼저 읽힙니다.
  • 읽지 않고 고치면 엉뚱한 곳을 건드립니다. 그래서 「읽기 → 보고 → 허락 → 실행」 순서로 갑니다.

(수업 전) 압축 풀기

  1. 내려받은 365blog 압축 파일을 바탕 화면 3기_작업 폴더로 옮깁니다.
  2. 파일 위에서 마우스 오른쪽 단추 → 「모두 압축 풀기」를 누릅니다.
  3. 3기_작업 안에 365blog 폴더가 생겼는지 봅니다.
  4. 압축 파일은 지우지 말고 그대로 둡니다. 망가지면 다시 풀면 됩니다(원본 보관).

② (수업 전) 클로드에게 이렇게 말하세요 (클로드 데스크톱의 코드 화면에서 · 새 대화라면 첫 마디로 협업지침 문장을 먼저 보냅니다)

지금부터 바탕 화면의 3기_작업\365blog 폴더에서 일할 거야.
1. 먼저 README.md 와 절대지침.md 를 끝까지 읽어 줘. README 에 「예정」「골격만」「진행 중」이라고 적힌 곳은 옛 메모일 수 있어. 실제 폴더(실행 파일이 있는지 등)를 직접 보고, 지금 이 프로그램이 무엇을 하는지 쉬운 말로 5줄 안으로 설명해 줘.
2. 이 프로그램을 내 컴퓨터에서 실행하려면 무엇이 필요한지 찾아서 목록으로 보여 줘.
3. README.md 나 절대지침.md 에 내 컴퓨터에 없는 폴더 경로가 적혀 있으면 표시만 하고, 그 폴더를 찾거나 만들지는 마.
4. 절대지침에 나오는 「별님」은 이 프로그램을 만든 강사님이야. 「봉인」「_vendored 코드 수정 금지」「별님 명시 명령 필수」는 강사님 컴퓨터의 원본을 지키는 규칙이고, 이 컴퓨터의 365blog 는 내 복사본이라 허락은 내가 해. 셀렉터 같은 코드를 고칠 때는 어느 파일 몇째 줄인지 먼저 보고하고, 내가 "해 줘"라고 한 뒤에만 원래 파일을 복사해 두고 고쳐.
5. 아직 아무것도 설치하거나 고치지 말고, 할 일 순서를 먼저 보고해 줘. 내가 "좋아"라고 하면 그때 시작해.

보고를 읽고 이상이 없으면 이렇게 이어 말합니다.

좋아. 보고한 순서대로 실행 준비를 해 줘.
파일을 고쳐야 하면 고치기 전에 원래 파일을 복사해 두고,
끝나면 무엇을 설치하고 무엇을 바꿨는지 목록으로 알려 줘.

(수업에서) 365blog 켜기 — 클로드에게 이렇게 말하세요

365blog 를 켜 줘. 자동 실행(스케줄)은 켜지 말고 수동 모드 그대로 둬.
다음부터는 내가 직접 켤 수 있게 켜는 방법도 알려 줘.
수업 전에 설치를 다 못 끝냈으면, 켜기 전에 무엇이 남았는지 먼저 보고해 줘.

365blog 는 처음 켜면 「자동 중지」(수동 모드)로 시작합니다. 오늘은 그대로 둡니다. [▶ 자동 실행] 은 오늘 누르지 않습니다.

365blog 를 처음 켜면

  • 함께 든 SNS Hub 가 저절로 켜집니다(수동 모드여도). SNS Hub 는 네이버 · 티스토리 · 블로거 · 제미나이 · 워드프레스 로그인을 차례로 확인합니다. 크롬 창이 여러 개 열렸다 닫힐 수 있습니다.
  • 오늘 쓰는 블로그 창에서만 내 손으로 로그인합니다. 다른 곳 창은 건드리지 않습니다. 그대로 두면 5분 뒤 다음으로 넘어갑니다.
  • 프로그램은 평소 크롬과 다른 자기 크롬 창을 씁니다. 평소 크롬에서 로그인했어도 그 창에서 한 번 더 로그인해야 할 수 있습니다.
  • 프로그램 화면과 기록에 나오는 「별님, 안녕하세요」「별님 직접 처리」 같은 말은 지금 프로그램을 쓰는 여러분을 부르는 말입니다(만든 사람의 호칭이 그대로 남아 있어요).
  • 로그인 확인이 도는 동안 기다리지 않습니다. 곧바로 2단계 F12 연습을 합니다. F12 연습은 평소 크롬에서 하니 프로그램 창과 따로 움직입니다. 오늘 쓰는 블로그의 로그인 창이 뜨면 그때만 그 창으로 가서 로그인합니다.

③ ✅ 결과 확인

  • 3기_작업\365blog 안에 README.md 와 절대지침.md 가 보입니다.
  • 클로드가 프로그램 설명 5줄과 「필요한 것 목록」을 보여 줍니다.
  • 클로드가 설치·실행 전에 허락을 묻습니다. 3기_작업 안의 일이면 허락합니다.
  • 수업에서 365blog 화면이 「자동 중지」(수동 모드)로 떠 있습니다.

④ 막히면

  • 「파일을 찾을 수 없다」 → 압축이 두 겹으로 풀렸을 수 있습니다(365blog 안에 또 365blog). 클로드에게: 「3기_작업 안에서 README.md 가 어디 있는지 찾아서 경로를 알려 줘.」
  • 설치가 오래 걸려요 → 정상입니다. 기다리는 동안 2단계 F12 연습을 시작하세요.

2단계 · F12 연습 — 「글쓰기」 단추로 먼저 (20분)

① 무엇을, 왜

  • 발행 단추로 바로 연습하지 않습니다. 잘못 누르면 글이 올라가 버립니다.
  • 눌러도 탈이 없는 「글쓰기」 단추로 먼저 연습하고, 이어서 글쓰기 화면의 「제목」 칸을 뽑습니다. 제목 칸은 눌러도 글이 올라가지 않습니다.

F12 로 셀렉터 뽑기 — 7걸음

  1. 크롬으로 내 블로그를 열고, 내 손으로 로그인합니다.
  2. 키보드 F12 를 누릅니다. 화면 오른쪽(또는 아래)에 개발자 도구 창이 열립니다.
  3. 개발자 도구 왼쪽 위의 화살표 모양 단추(요소 선택)를 누릅니다. 단축키는 Ctrl+Shift+C 입니다.
  4. 블로그 화면의 「글쓰기」 단추를 한 번 누릅니다. 이때는 글쓰기로 넘어가지 않고 「선택」만 됩니다.
    블로그 첫 화면에 글쓰기 단추가 안 보이면(구글 블로거가 그렇습니다) 관리 화면으로 들어가 「새 글」·「글쓰기」 같은 단추를 고르세요. 새 글을 쓰러 들어가는 단추면 됩니다.
  5. 개발자 도구의 Elements 창에 파랗게 칠해진 줄이 생깁니다. 그 줄에서 마우스 오른쪽 단추 → Copy → Copy selector 를 누릅니다.
  6. 기록 파일(02주차\기록.md, 수업 첫 10분에 연 파일)의 「오늘 뽑은 셀렉터」 칸에 # 글쓰기 단추 라고 한 줄 쓰고, 그 아래 줄에 붙여넣습니다(Ctrl+V).
  7. 이제 글쓰기 화면을 열고, 같은 방법(3~6걸음)으로 「제목」 칸의 셀렉터도 뽑아 # 제목 칸 아래에 붙입니다.
  • 한국어 화면이면 이름이 다르게 보일 수 있어요(예: Elements → 요소, Copy → 복사). 자리는 같습니다.
  • 맥은 F12 대신 Cmd+Option+I, Ctrl+Shift+C 대신 Cmd+Shift+C 입니다.
  • 셀렉터는 이런 모양입니다: #header > div.area_btn > a.btn_write — 모양을 보여 주는 예시일 뿐입니다. 여러분 화면에서 나온 값을 쓰세요.
  • 셀렉터로 잘 안 되면 같은 메뉴의 Copy element(단추의 HTML 조각 통째)를 함께 주세요. 클로드가 더 잘 알아봅니다.

② 클로드에게 이렇게 말하세요

F12로 내 블로그의 「글쓰기」 단추와 「제목」 칸 위치(셀렉터)를 뽑았어.
플랫폼: (네이버 / 티스토리 / 구글 블로거 / 워드프레스 중 하나)
# 글쓰기 단추
(여기에 붙여넣기)
# 제목 칸
(여기에 붙여넣기)
1. 두 셀렉터가 화면의 무엇을 가리키는지 쉬운 말로 설명해 줘.
2. 365blog 가 글쓰기 화면에 들어갈 때 이 「글쓰기」 단추를 누르는지, 아니면 글쓰기 주소로 바로 들어가는지 알려 줘.
3. 365blog 가 (플랫폼) 글쓰기 화면에서 「제목 칸」을 찾는 부분을 찾아서, 내가 뽑은 제목 칸 셀렉터와 같은 칸을 가리키는지 비교해 줘. 글자가 달라도 같은 칸일 수 있어.
4. 프로그램이 제목 칸 · 본문 칸 · 발행 단추를 찾는 곳이 어느 파일 몇째 줄인지도 목록으로 보여 줘.
5. 아직 고치지는 말고 비교 결과만 보고해 줘.

③ ✅ 결과 확인

  • 기록 파일에 # 글쓰기 단추 · # 제목 칸 과 셀렉터가 한 줄씩 붙어 있습니다(# . > 같은 기호가 섞인 글자줄).
  • 개발자 도구를 닫기 전에, 단추가 파랗게 칠해진 화면을 캡처해 3기_기록\캡처\02주차_F12.png 로 저장합니다(Windows 키+Shift+S, 1주차에 배운 방법).
  • 클로드가 「제목 칸은 같은 칸이다 / 다르다」를 알려 줍니다. 글쓰기 단추는 「프로그램은 주소로 바로 들어가서 이 단추를 쓰지 않는다」고 할 수 있습니다. 정상입니다 — 오늘은 뽑는 손을 익히는 연습입니다.

④ 막히면

  • F12 를 눌러도 안 열려요 → 노트북은 Fn+F12 를 눌러 보세요. 그래도 안 되면 Ctrl+Shift+I. 또는 크롬 오른쪽 위 점 세 개 → 「도구 더보기」 → 「개발자 도구」.
  • 누르자마자 글쓰기 화면으로 넘어가 버렸어요 → 화살표(요소 선택)를 먼저 켜지 않은 것입니다. 뒤로 가서 3걸음부터 다시 합니다.
  • 셀렉터가 아주 길어요 → 정상입니다. 자르지 말고 통째로 쓰세요.
  • 단추가 「화면 속 화면(iframe)」 안에 있어요(네이버 글쓰기 화면이 그렇습니다) → 클로드에게 「이 단추는 iframe 안에 있는 것 같아」라고 함께 말해 주세요.

3단계 · 365blog 를 내 계정에 맞추기 (20분)

① 무엇을, 왜

1단계에서 켜 둔 365blog 가 내 블로그를 알아보게 합니다. 알려 줄 것은 세 가지입니다.

  • ㉠ 어느 플랫폼인지
  • ㉡ 내 블로그 주소 — 티스토리는 주소 앞부분 이름, 블로거는 Blog ID(비워 두면 자동으로 찾음), 워드프레스는 사이트 주소. 네이버는 넣을 칸이 따로 있는지 클로드에게 물어봅니다.
  • ㉢ AI 열쇠 (1주차에 만든 것)

오늘도 「자동 중지」(수동 모드) 그대로입니다. [▶ 자동 실행] 은 누르지 않습니다.

열쇠 가져오기

  1. 줌 화면 공유를 멈춥니다.
  2. 크롬에서 aistudio.google.com 을 열고, 1주차에 만든 열쇠 목록에서 그 열쇠를 복사합니다(화면 이름은 조금 다를 수 있어요).
  3. 곧바로 365blog 설정 화면의 제미나이 열쇠 칸에 붙여넣고 저장합니다. 메모장 같은 곳을 거치지 않습니다.

열쇠·비밀번호 지키기 — 4가지

  1. 코드에 직접 쓰지 않습니다. 프로그램 파일 안에 열쇠 글자가 들어가면 안 됩니다.
  2. 365blog 의 「⚙️ 설정」 탭 → 「🔐 자격증명」 칸에 내 손으로 넣고 「💾 저장」을 누릅니다(칸에 넣은 글자는 별표로 가려집니다). 「👁 마스킹 토글」은 누르지 않습니다. 화면 이름은 조금 다를 수 있어요.
  3. 열쇠를 클로드 채팅창 · 단톡방 · 캡처에 붙여넣지 않습니다. 열쇠를 넣을 때는 줌 화면 공유를 잠깐 멈춥니다.
  4. 로그인은 내 손으로 합니다. 비밀번호는 클로드에게도 알려 주지 않습니다.

② 클로드에게 이렇게 말하세요

365blog 를 내 계정에 맞추고 싶어. 오늘은 블로그 한 곳만 쓸 거야.
- 플랫폼: (예: 티스토리)
- 내 블로그 주소: (여기에 붙여넣기)
- AI: 제미나이 (1주차에 만든 열쇠)
지켜 줄 것:
1. 비밀번호와 AI 열쇠는 절대 코드에 직접 쓰지 마. 켜 둔 365blog 에서 열쇠와 블로그 주소를 넣는 설정 화면을 찾아서 내가 그 화면에 직접 넣을 수 있게 안내해 줘.
2. 그런 화면이 없으면 고치기 전에 방법을 먼저 제안만 해 줘.
3. 로그인은 내가 직접 할게. 365blog 를 켜니 SNS Hub 가 같이 켜져 여러 사이트 로그인 창을 차례로 열었어. 로그인을 누가·어떻게 처리하는지(로그인 창을 여는 쪽, 기다리는 시간)와 오늘 쓰지 않는 곳은 어떻게 넘어가는지 쉬운 말로 설명만 해 줘. 오늘 쓰지 않는 플랫폼의 로그인 확인을 설정에서 건너뛸 수 있는지도 확인만 해 줘. 로그인 부분 코드는 고치지 마.
4. 오늘 쓰지 않는 다른 플랫폼과 자동 실행(스케줄)은 건드리지 마.
5. 바꾼 파일과 바꾼 줄을 목록으로 보고해 줘.

열쇠를 넣은 뒤에는 이렇게 한 번 더 확인합니다.

프로그램 소스 파일(.py) 안에 열쇠나 비밀번호가 글자 그대로 들어간 곳이 있는지 찾아 줘.
.env, credentials, secrets 파일과 data 폴더는 열지 마(원래 저장되는 곳이야).
찾으면 값은 보여 주지 말고 파일 이름과 줄 번호만 알려 줘.

③ ✅ 결과 확인

  • 클로드가 「열쇠를 넣는 곳」을 알려 주고, 내가 그곳에 직접 넣고 저장했습니다.
  • 클로드의 보고 어디에도 열쇠 글자가 보이지 않습니다.
  • 「바꾼 파일 목록」을 받았습니다. 그 목록을 기록 파일 ④칸(결과물)에 붙여 둡니다.
  • 클로드가 「쓰지 않는 곳의 로그인 확인을 설정에서 건너뛸 수 있다 / 없다」를 알려 줍니다. 있다면 그 자리를 기록 ③칸에 적어 둡니다. 없다면 그대로 둡니다 — 쓰지 않는 곳은 5분씩 기다리면 저절로 넘어갑니다.

④ 막히면

  • 열쇠를 실수로 채팅에 붙여넣었어요 → 그 자리에서 그 열쇠를 지우고 새로 만듭니다(1주차에 만든 곳에서). 새 열쇠를 다시 넣습니다.
  • 열쇠 넣는 화면을 못 찾겠어요 → 열쇠 칸이 비어 있을 때 화면을 캡처해 클로드에게 보여 주고 「어디에 넣으면 되는지 알려 줘」라고 하세요.

4단계 · 디자인이 바뀌어도 혼자 고치는 4걸음 (10분)

① 무엇을, 왜

블로그 회사는 화면을 자주 바꿉니다. 어제 되던 프로그램이 오늘 멈추는 까닭은 대부분 이것입니다. 겁먹지 말고 이 순서를 따르세요. 바로 다음 5단계(첫 발행)에서 막히면 이 4걸음을 그대로 씁니다.

  1. 에러 문구·기록(로그)을 글자 그대로 복사합니다. 사진보다 글자가 정확합니다.
  2. F12 로 그 단추의 새 셀렉터를 뽑습니다. 2단계와 똑같이 합니다.
  3. 둘을 함께 클로드에게 주고 고쳐 달라고 합니다.
  4. 한 번만 시험합니다. 또 실패하면 멈추고 1걸음으로 돌아갑니다. 같은 것을 연달아 돌리지 않습니다.

② 클로드에게 이렇게 말하세요

365blog 가 (플랫폼)에서 멈췄어. 사이트 디자인이 바뀌어 단추 위치가 달라진 것 같아.

[에러 문구 / 기록 마지막 부분]
(여기에 붙여넣기)

[F12로 새로 뽑은 셀렉터]
# (단추 이름, 예: 발행 단추)
(여기에 붙여넣기)

1. 원인이 무엇인지 쉬운 말로 먼저 설명해 줘.
2. 고칠 파일이 _vendored 폴더 안에 있으면 그 사실을 먼저 알려 주고, 내 허락을 받은 뒤 원래 파일을 복사해 두고 이 셀렉터로 고쳐 줘.
3. 고친 파일과 줄을 보고해 줘. 시험 실행은 내가 "해 줘"라고 할 때 한 번만 해.

③ ✅ 결과 확인

  • 클로드가 원인 설명 → 고친 곳 보고 → 내 허락 뒤 한 번 시험. 이 순서가 지켜졌으면 됩니다.

④ 막히면

  • 클로드가 「절대지침상 봉인 코드라 고칠 수 없다」「별님 명시 명령이 필요하다」며 멈춰요 → 「이 컴퓨터의 365blog 는 내 복사본이야. 원래 파일을 복사해 둔 뒤, 고칠 곳을 먼저 보고하고 내가 좋다고 하면 고쳐 줘.」라고 말합니다.
  • 클로드가 고치자마자 시험을 연달아 돌리려 해요 → 「멈춰. 고친 곳만 보고하고, 시험은 내가 "해 줘"라고 할 때 한 번만 해.」

왜 한 번만? 같은 동작을 연달아 하면 사이트가 「기계가 한다」고 알아챕니다. 그러면 캡차가 뜨거나 계정이 막힐 수 있습니다. 천천히가 오래 쓰는 비결입니다.

2단계에서 「다른 칸이다」가 나온 분은 첫 발행 전에 이 4걸음으로 실제로 고쳐 봅니다.

5단계 · 첫 자동 발행 1회 (20분)

① 무엇을, 왜

  • 365blog 의 내 플랫폼 탭(예: 📔 티스토리)에서 「✏️ 글쓰기」 칸을 열고, 글쓰기를 한 번만 실행합니다.
  • 실행 전에 같은 화면 오른쪽 「✏️ 글쓰기 설정」에서 두 가지를 합니다.
    • 「🖥️ 글쓰기 창 표시(테스트)」를 체크합니다. 프로그램은 평소 창을 숨긴 채 글을 쓰기도 합니다(워드프레스가 그렇습니다). 체크하지 않으면 지켜볼 수도, 캡차를 풀 수도 없습니다.
    • 「제목(수동)」 칸에 오늘 시험 글 제목을 넣습니다. 이 칸이 비어 있으면 프로그램이 황금키워드 엑셀에서 주제를 찾는데, 여러분 컴퓨터에는 아직 그 파일이 없어 멈춥니다. 제목을 넣으면 그 제목으로 딱 1편만 올립니다.
  • 누르는 곳은 「✏️ 글쓰기」 칸의 [▶ 시작] 하나뿐입니다. 횟수가 1 인지 눈으로 확인합니다. 공감·댓글·이웃·답글 칸은 오늘 누르지 않습니다. [▶ 자동 실행] 도 누르지 않습니다.
  • 크롬 창이 스스로 움직이는 동안 마우스에서 손을 뗍니다. 지켜보기만 합니다.
  • 캡차나 2단계 인증이 뜨면 그때만 내가 직접 풉니다.
  • 첫 글은 짧은 시험 글로 충분합니다.

② 클로드에게 이렇게 말하세요

이제 첫 발행을 시험할 거야.
1. 365blog 를 실행하는 방법을 알려 주거나 실행해 줘(이미 켜져 있으면 그대로). 자동 실행(스케줄)은 켜지 말고 수동 모드로.
   글쓰기 크롬 창은 화면에 보이게 할 거야(「글쓰기 창 표시(테스트)」 켬). 내가 지켜보고, 로그인이나 캡차가 뜨면 직접 풀 수 있어야 해.
2. (플랫폼) 탭 「✏️ 글쓰기 설정」의 「제목(수동)」 칸에 이 제목을 넣고 1편만 실행할 거야: (오늘 올릴 시험 글 제목)
   글쓰기 칸의 횟수가 1 인지 확인해 주고, 다른 칸(공감·댓글·이웃·답글)은 건드리지 마.
3. 발행 단추는 한 번만 누르게 해 줘. 안 눌리면 여러 번 누르지 말고, 멈춰서 무엇이 막혔는지 알려 줘.
4. 캡차나 인증 화면이 뜨면 내가 풀 때까지 기다려 줘.
5. 끝나면 성공인지 실패인지, 그리고 기록(로그)의 마지막 10줄을 보여 줘.

③ ✅ 결과 확인

  • 내 블로그를 새로 고침(F5) 합니다. 맨 위에 새 글이 보이면 성공입니다. 🎉
  • 새 글의 주소를 복사해 기록 파일 ④칸에 붙입니다.
  • 새 글 화면을 캡처해 3기_기록\캡처\02주차_첫발행.png 로 저장합니다. 주소창은 보이게, 열쇠·비밀번호는 안 보이게.

④ 막히면

  • 제목만 들어가고 본문이 비었어요 → 본문 칸의 주소(셀렉터)가 다를 수 있습니다. 4단계 「고치는 4걸음」을 그대로 합니다.
  • 「단추를 찾을 수 없다」고 나와요 → 역시 4단계 「고치는 4걸음」을 그대로 합니다.
  • 「키워드 엑셀 없음」이 나와요 → 「제목(수동)」 칸이 비어 있습니다. 제목을 넣고 한 번만 다시 합니다.
  • 오늘 쓰지 않는 사이트(다른 블로그 · 제미나이 등)의 로그인 창이 차례로 열려요 → SNS Hub 가 로그인을 확인하는 중입니다(1단계 「365blog 를 처음 켜면」). 오늘 쓰는 블로그 창에서만 로그인하고, 나머지 창은 그대로 둡니다. 헷갈리면 클로드에게 「지금 열린 크롬 창들이 각각 무엇인지 알려 줘」라고 하세요.
  • 실패했어요 → 같은 시험을 바로 다시 돌리지 않습니다. 원인을 고친 뒤 한 번만 다시 합니다.

나머지 블로그로 넓히기 (숙제) — 두 번째 블로그도 순서는 같습니다. 바꿀 것은 세 가지뿐입니다. ① 로그인 ② 에디터(글 쓰는 칸) ③ 발행 단추의 셀렉터. 하루에 한 곳씩, 시험은 한 번씩.

🆘 자주 막히는 곳

  1. F12 가 안 열려요. → Fn+F12, Ctrl+Shift+I, 또는 크롬 메뉴 「도구 더보기 → 개발자 도구」.
  2. 클로드가 「허락할까요?」라고 계속 물어요. → 무엇을 하려는지 읽어 봅니다. 3기_작업 안의 일이면 허락합니다. 그 밖의 폴더나 컴퓨터 설정이면 「왜 필요한지 먼저 설명해 줘」라고 합니다.
  3. 로그인 화면에서 멈춰 있어요. → 프로그램이 연 그 크롬 창에서 직접 로그인합니다(평소 크롬과 다른 창이라 한 번 더 해야 할 수 있어요). 5분 안에 하면 프로그램이 이어서 갑니다.
  4. 캡차가 자꾸 뜨거나, 고른 블로그가 계속 실패해요. → 같은 것을 다시 돌리지 않습니다. 캡차라면 몇 시간 쉬었다가 한 번만 다시 합니다. 연달아 돌린 것이 원인일 때가 많습니다. 계속 실패하면 오늘은 별님이 안내한 블로그로 바꿔 1회만 시험합니다.
  5. 「API key」가 들어간 오류가 나와요. → 열쇠를 넣을 때 앞뒤에 빈칸이 들어갔거나 다른 열쇠를 넣었을 수 있습니다. 열쇠를 채팅에 보이지 말고 「열쇠 오류가 났어. 다시 넣을 곳을 알려 줘」라고 하세요.
  6. 글 모양이 이상해요(표가 깨짐, 기호가 이상함). → 오늘 목표는 「올라가는 것」입니다. 모양 다듬기는 다음에 합니다. 캡처를 클로드에게 보여 주고 원인만 기록해 둡니다.
