🛠 단계별 실습

먼저 그림 한 장으로 — 내 홈페이지가 인터넷에 올라가는 길

  1. index.html = 홈페이지의 첫 장입니다. 지금은 내 컴퓨터 안에만 있습니다.
  2. 깃허브(GitHub) = 인터넷 위의 무료 파일 보관함입니다. 보관함 한 칸을 저장소(repository)라고 부릅니다.
  3. GitHub Pages = 저장소에 든 index.html 을 누구나 볼 수 있는 홈페이지로 보여 주는 무료 기능입니다.
  4. 그래서 순서는 고친다(클로드) → 올린다(깃허브) → 켠다(Pages) → 주소를 받는다입니다.

⚠️ 여기는 공개 인터넷입니다. 집 주소·휴대전화 번호·생년월일은 페이지에 올리지 않습니다. 연락은 신청 버튼으로 받습니다.

0단계 · 랜딩페이지 샘플 꺼내기 (압축 풀기)

3기_작업 폴더 안에서 index.html 이 들어 있는 랜딩페이지 샘플 폴더를 찾아 줘.

집 주소·휴대전화 번호는 넣지 마.

3단계 · 깃허브 가입하기 (이메일 인증)

무엇을, 왜 — 깃허브(GitHub)는 인터넷 위의 무료 파일 보관함입니다. 여기에 올린 파일을 홈페이지로 켤 수 있습니다. 가입은 본인이 직접 합니다.

  1. 크롬에서 github.com 을 엽니다.
  2. 오른쪽 위 Sign up(가입하기)을 누릅니다.
  3. 화면 안내에 따라 이메일, 비밀번호, 아이디(Username)를 넣습니다.
  4. 사람인지 확인하는 퍼즐이 나오면 직접 풉니다.
  5. 이메일로 온 숫자(인증 코드)를 화면에 넣습니다.
  6. 요금제를 묻는 화면이 나오면 무료(Free)를 고릅니다.

🔑 아이디가 주소 앞부분이 됩니다. 아이디.github.io 의 「아이디」 자리입니다. 명함에 적을 이름이니 짧고 읽기 쉽게, 영어 소문자·숫자로 정합니다. 하이픈(-)은 낱말 사이에만 씁니다(맨 앞·맨 끝에 쓰거나 두 개를 잇달아 쓸 수 없습니다). 나중에 바꾸면 주소도 바뀝니다.

🔒 깃허브 비밀번호와 인증 번호는 클로드·단톡방·기록 어디에도 적지 않습니다.

4단계 · 저장소 만들기 (Public)

무엇을, 왜 — 저장소(repository)는 보관함 한 칸입니다. 홈페이지 파일만 담을 칸을 하나 만듭니다. 저장소 이름이 주소 뒷부분이 됩니다.

  1. 깃허브 화면 오른쪽 위 + 를 누르고 New repository(새 저장소)를 고릅니다.
  2. Repository name(저장소 이름)에 영어 소문자로 짧게 적습니다. 예: homepage
  3. 공개 범위에서 Public(공개)을 고릅니다.
  4. README(설명 파일)를 함께 만드는 칸이 보이면 켜 둡니다. 그러면 다음 단계의 Add file 단추가 바로 보입니다.
  5. 맨 아래 Create repository(저장소 만들기)를 누릅니다.

왜 Public 인가요? 무료 계정에서 GitHub Pages 를 쓰려면 공개 저장소여야 합니다. 그래서 저장소에 올린 파일은 누구나 볼 수 있습니다. 홈페이지 파일만 올립니다. 365blog·e_book_maker 프로그램 소스는 절대 올리지 않습니다(수강생 외 재배포 금지, 열쇠가 새어 나갈 위험).

💬 클로드에게 이렇게 말하세요 (화면이 헷갈릴 때, 캡처를 함께 붙여 넣기)

지금 깃허브에서 새 저장소를 만드는 화면이야. 캡처를 붙여 넣을게.
홈페이지용 공개(Public) 저장소를 만들려면
어느 칸에 무엇을 넣고 무엇을 눌러야 하는지 위에서부터 순서대로 알려 줘.

✅ 결과 확인

  • 주소창이 github.com/아이디/homepage 모양이다.
  • 저장소 이름 옆에 Public 표시가 보인다.

🔧 막히면

  • 저장소 이름에 한글이나 띄어쓰기를 넣었다 → 영어 소문자 이름으로 새로 만듭니다. 새로 만드는 편이 쉽습니다.
  • Private(비공개)로 만들었다 → 이번 실습에서는 Public 으로 새 저장소를 만드는 편이 빠릅니다.

5단계 · 파일 올리기 (Add file → Upload files → Commit changes)

무엇을, 왜 — 2단계에서 만든 내홈페이지 폴더 안의 파일들을 저장소에 올립니다. 올리기 전에 클로드에게 개인정보 검사를 먼저 맡깁니다.

💬 클로드에게 이렇게 말하세요 (올리기 전 검사)

3기_작업\내홈페이지 폴더를 깃허브 공개 저장소에 올리려고 해.
① 올릴 파일 목록을 보여 주고, index.html 이 폴더 맨 위에 있는지 확인해 줘.
② 파일 안에 열쇠(API 키)·비밀번호·전화번호·집 주소·이메일 같은 개인정보가 있는지 검사해 줘.
③ 샘플에서 온 다른 사람 이름·사진·원래 신청 링크가 남아 있는지, index.html 이 쓰지 않는 샘플 파일(설명서·다른 페이지)이 있는지도 알려 줘.
고치지는 말고 결과만 보고해 줘.
  1. 저장소 첫 화면에서 Add file(파일 추가)을 누르고 Upload files(파일 올리기)를 고릅니다.
  2. 바탕 화면 3기_작업 → 내홈페이지 폴더를 엽니다.
  3. 폴더 안의 파일을 모두 선택합니다(Ctrl+A).
  4. 선택한 파일을 깃허브 화면의 올리기 칸으로 끌어다 놓습니다.
  5. 아래 초록색 Commit changes(변경 확정 = 저장)를 누릅니다.

빈 저장소라서 Add file 단추가 안 보이면, 화면 가운데의 「uploading an existing file」(이미 있는 파일 올리기) 글씨를 누릅니다. 같은 올리기 화면이 열립니다.

✅ 결과 확인

  • 저장소 첫 화면 파일 목록에 index.html 이 바로 보인다(폴더 안이 아니라).
  • 샘플에 그림·스타일 파일이 따로 있었다면 그것도 함께 보인다.

🔧 막히면

  • 내홈페이지 라는 폴더째 올라갔다 → 폴더를 열고 안의 파일만 다시 올립니다. 남은 폴더는 홈페이지에 영향이 없습니다.
  • 끌어다 놓기가 안 된다 → 올리기 화면의 「choose your files」(파일 고르기) 글씨를 눌러 파일을 고릅니다. 단, 이 방법으로는 폴더가 올라가지 않습니다. 샘플 안에 폴더(그림·스타일)가 있으면 끌어다 놓기를 다시 해 보거나, 화면을 캡처해 클로드에게 보여 주세요.

6단계 · GitHub Pages 켜기

무엇을, 왜 — 저장소에 올린 index.html 을 누구나 볼 수 있는 홈페이지로 켜는 단계입니다. 무료입니다.

  1. 저장소 위쪽 메뉴에서 Settings(설정)를 누릅니다.
  2. 왼쪽 목록에서 Pages(페이지)를 누릅니다.
  3. Source(원본) 칸을 Deploy from a branch(가지에서 배포)로 둡니다.
  4. Branch(가지) 칸에서 main 을 고르고, 옆 폴더 칸은 /(root)(맨 위 폴더)로 둡니다.
  5. Save(저장)를 누릅니다.
  6. 몇 분 뒤 이 화면을 새로고침하면 위쪽에 내 주소가 나타납니다.

반영까지 몇 분 걸릴 수 있습니다. 바로 안 열려도 고장이 아닙니다. 기다리는 동안 7단계 신청 버튼을 만듭니다.

💬 클로드에게 이렇게 말하세요 (주소가 404 로 나올 때, 캡처 2장을 함께)

저장소 첫 화면 캡처와 Settings → Pages 화면 캡처를 붙여 넣을게.
무엇이 잘못됐는지 찾아서, 내가 고칠 순서를 하나씩 알려 줘.

✅ 결과 확인

  • Pages 화면 위쪽에 https://아이디.github.io/저장소이름/ 주소가 보인다.
  • 그 주소를 누르면 2단계에서 본 내 홈페이지가 열린다.

🔧 막히면

  • Settings 가 안 보인다 → 브라우저 창을 넓힙니다. 메뉴가 「…」 안에 숨어 있을 수 있습니다.
  • Branch 칸에 main 이 없다 → 아직 파일이 안 올라간 것입니다. 5단계로 돌아갑니다.

화면 이름은 조금 다를 수 있어요. 막히면 화면을 캡처해 클로드에게 보여 주세요.

7단계 · 신청 버튼 연결하기 (구글 설문지 또는 카카오 오픈채팅)

무엇을, 왜 — 홈페이지를 본 분이 신청 버튼을 누르면 내게 연락이 오게 합니다. 전화번호를 올리지 않아도 됩니다. 둘 중 하나를 고릅니다.

설문지나 오픈채팅 링크를 이미 만들어 왔다면 가·나는 건너뜁니다(설문지라면 가의 7번 알림 켜기만 합니다). 2단계에서 그 링크를 이미 넣었다면 「링크 걸기」도 건너뛰고 ✅ 결과 확인으로 갑니다.

가. 구글 설문지 (추천)

  1. 크롬에서 구글에 로그인하고 forms.google.com 을 엽니다.
  2. 새 양식을 만드는 + 모양(빈 양식)을 누릅니다.
  3. 제목을 적습니다. 예: 「○○ 상담 신청」. 제목 아래 설명 칸에는 「모으는 것: 성함·연락처 / 쓰는 곳: 상담 신청 확인 / 보관: 상담이 끝나면 지웁니다」 한 줄을 적습니다.
  4. 질문을 3개만 만듭니다: 성함(단답형) · 연락받을 방법(단답형) · 궁금한 점(장문형).
  5. 오른쪽 위 단추(화면에 따라 「보내기」 또는 「게시」)를 누릅니다.
  6. 응답하는 분께 보낼 링크(🔗 모양)를 복사합니다.
  7. 위쪽 「응답」 탭에서 ⋮(점 세 개) → 「새 응답 이메일 알림 받기」를 켭니다. 그래야 신청이 오면 메일로 알 수 있습니다.

화면 이름은 조금 다를 수 있어요. 막히면 화면을 캡처해 클로드에게 보여 주세요.

설문지는 꼭 필요한 것만 묻습니다. 받은 연락처는 설명 칸에 적은 그 일에만 씁니다.

나. 카카오 오픈채팅

  • 카카오톡에서 1:1 오픈채팅방을 만들고, 링크 공유에서 주소를 복사합니다. 주소는 https://open.kakao.com/o/ 로 시작합니다. 메뉴 위치는 카카오톡 버전에 따라 다를 수 있습니다.

💬 클로드에게 이렇게 말하세요 (링크 걸기)

버튼을 누르면 새 탭으로 열리게 해 줘. 신청 버튼이 여러 개면 모두 바꿔 줘.
다른 곳은 고치지 마.

8단계 · 내 주소 확인하고 휴대폰으로도 열어 보기

  3. 휴대폰에서 그 주소를 눌러 엽니다.
  4. 글자 크기, 줄 바꿈, 신청 버튼을 확인합니다.

💬 클로드에게 이렇게 말하세요 (휴대폰에서 어색할 때)

✅ 결과 확인 — 오늘의 결과물

이 주소는 5주차 과제(6주차 시연 준비 네 줄)에 적고, 책이 승인되면 이 홈페이지에 책 소개를 더합니다. 6주차 시연회에서는 내 결과물로 보여 줍니다.

🔧 막히면

  • 휴대폰에서 404 가 나온다 → 주소를 끝의 / 까지 다 보냈는지, PC에서 연 주소와 한 글자도 다르지 않은지 봅니다. 손으로 치지 말고 PC에서 복사해 「나와의 채팅」으로 보냅니다. PC에서도 404 면 아래 「자주 막히는 곳」 1번을 따릅니다.

🆘 자주 막히는 곳

  2. 고쳐서 올렸는데 옛 화면이 그대로다 → 반영까지 몇 분 걸릴 수 있습니다. PC는 Ctrl+F5, 휴대폰은 창을 닫았다가 다시 엽니다.
  3. 사진이나 꾸밈이 안 나온다 → 그림·스타일 파일을 같이 올렸는지 봅니다. 깃허브는 파일 이름의 대문자·소문자를 구별합니다(Photo.jpg 와 photo.jpg 는 다른 파일).
  4. 신청 버튼이 편집 화면이나 「권한 필요」로 간다 → /edit 주소를 넣은 것입니다. 응답하는 분께 보낼 링크로 바꿉니다.
  5. 한글이 이상한 글자로 깨진다 → 클로드에게 「index.html 을 UTF-8 로 저장하고 charset 설정을 확인해 줘」라고 말합니다.
  6. 인증 메일이 안 온다 → 스팸함·프로모션함을 보고, 몇 분 뒤 다시 보내기를 누릅니다.
