처음 보는 말은 막힐 때마다 이 상자로 돌아와 보세요.

  • 저장소(repository) = 보관함 한 칸. 홈페이지 하나 = 저장소 하나
  • Public(공개) = 누구나 볼 수 있음. 반대말은 Private(비공개)

  • GitHub Pages = 저장소에 든 index.html 을 홈페이지로 보여 주는 무료 기능
  • 배포 = 인터넷에 내놓아 누구나 주소로 열 수 있게 하는 것
  • 404 = 「이 주소에는 아무것도 없어요」라는 표시. 대개 기다리거나 파일 자리를 고치면 풀립니다
  • 강력 새로고침(Ctrl+F5) = 기억해 둔 옛 화면 대신 새 화면을 다시 받아 오기

🛠 단계별 실습

먼저 그림 한 장으로 — 내 홈페이지가 인터넷에 올라가는 길

  1. index.html = 홈페이지의 첫 장입니다. 지금은 내 컴퓨터 안에만 있습니다.
  2. 깃허브(GitHub) = 인터넷 위의 무료 파일 보관함입니다. 보관함 한 칸을 저장소(repository)라고 부릅니다.
  3. GitHub Pages = 저장소에 든 index.html 을 누구나 볼 수 있는 홈페이지로 보여 주는 무료 기능입니다.
  4. 그래서 순서는 고친다(클로드) → 검사한다(🔒 비밀 지키기) → 올린다(깃허브) → 켠다(Pages) → 주소를 받는다입니다.

⚠️ 여기는 공개 인터넷입니다. 집 주소·휴대전화 번호·생년월일은 페이지에 올리지 않습니다. 연락은 신청 버튼으로 받습니다.

왜 하나요? 저장소(repository)는 보관함 한 칸입니다. 홈페이지 파일만 담을 칸을 하나 만듭니다. 저장소 이름이 주소 뒷부분이 됩니다.

이렇게 합니다

  1. 깃허브 화면 오른쪽 위 + 를 누릅니다.
  2. 펼쳐진 목록에서 New repository(새 저장소)를 고릅니다.
  3. Repository name(저장소 이름)에 영어 소문자로 짧게 적습니다. 예: homepage
  4. 공개 범위에서 Public(공개)을 고릅니다.
  5. README(설명 파일)를 함께 만드는 칸이 보이면 켜 둡니다. 그러면 다음 단계의 Add file 단추가 바로 보입니다.
  6. 맨 아래 Create repository(저장소 만들기)를 누릅니다.

왜 Public 인가요? 무료 계정에서 GitHub Pages 를 쓰려면 공개 저장소여야 합니다. 그래서 저장소에 올린 파일은 누구나 볼 수 있습니다. 홈페이지 파일만 올립니다. 365blog·e_book_maker 프로그램 소스는 절대 올리지 않습니다(수강생 외 재배포 금지, 열쇠가 새어 나갈 위험).

  • Private(비공개)로 만들었다 → 이번 실습에서는 Public 으로 새 저장소를 만드는 편이 빠릅니다.
  • 이름 칸 아래에 빨간 글씨가 나온다 → 같은 이름이 이미 있을 수 있습니다. homepage2 처럼 숫자를 붙이고, 그래도 안 되면 캡처를 붙여 클로드에게 「빨간 글씨가 왜 나왔는지 알려 줘」라고 묻습니다.

6단계 · 파일 올리기 (Add file → Upload files → Commit changes)

왜 하나요? 4단계에서 검사를 마친 내홈페이지 폴더 안의 파일들을 저장소에 넣습니다. 폴더째가 아니라 안의 파일들을 올려야 주소를 열 때 첫 화면이 바로 나옵니다.

이렇게 합니다

  1. 저장소 첫 화면에서 Add file(파일 추가)을 누릅니다.
  2. Upload files(파일 올리기)를 고릅니다.
  3. 파일 탐색기에서 바탕 화면 3기_작업 → 내홈페이지 폴더를 엽니다.
  4. 폴더 안 빈 곳을 한 번 누른 뒤, Ctrl+A 로 파일을 모두 선택합니다.
  5. 선택한 파일을 깃허브 화면의 올리기 칸으로 끌어다 놓습니다.
  6. 올리기 칸 아래에 파일 이름 목록이 다 나올 때까지 기다립니다.
  7. 맨 아래 초록색 Commit changes(변경 확정 = 저장)를 누릅니다.

빈 저장소라서 Add file 단추가 안 보이면, 화면 가운데의 「uploading an existing file」(이미 있는 파일 올리기) 글씨를 누릅니다. 같은 올리기 화면이 열립니다.

✅ 이렇게 보이면 성공

  • 저장소 첫 화면 파일 목록에 index.html 이 바로 보인다(폴더 안이 아니라).
  • 샘플에 그림·스타일 파일이 따로 있었다면 그것도 함께 보인다.

🧯 막히면

  • 내홈페이지 라는 폴더째 올라갔다 → 폴더를 열고 안의 파일만 다시 올립니다. 남은 폴더는 홈페이지에 영향이 없습니다.
  • 끌어다 놓기가 안 된다 → 올리기 화면의 「choose your files」(파일 고르기) 글씨를 눌러 파일을 고릅니다. 단, 이 방법으로는 폴더가 올라가지 않습니다. 샘플 안에 폴더(그림·스타일)가 있으면 끌어다 놓기를 다시 해 보거나, 화면을 캡처해 클로드에게 보여 주세요.

7단계 · GitHub Pages 켜기

왜 하나요? 저장소에 올린 index.html 을 누구나 볼 수 있는 홈페이지로 켜는 단계입니다. 이걸 켜야 주소가 생깁니다. 무료입니다.

이렇게 합니다

  1. 저장소 위쪽 메뉴에서 Settings(설정)를 누릅니다.
  2. 왼쪽 목록에서 Pages(페이지)를 누릅니다.
  3. Source(원본) 칸을 Deploy from a branch(가지에서 배포)로 둡니다.
  4. Branch(가지) 칸에서 main 을 고릅니다.
  5. 옆 폴더 칸은 /(root)(맨 위 폴더)로 둡니다.
  6. Save(저장)를 누릅니다.
  7. 몇 분 뒤 이 화면을 새로고침하면 위쪽에 내 주소가 나타납니다.

반영까지 몇 분 걸릴 수 있습니다. 바로 안 열려도 고장이 아닙니다. 기다리는 동안 8단계 신청 버튼을 만듭니다.

💬 클로드에게 이렇게 말하세요 (주소가 404 로 나올 때, 캡처 2장을 함께)

깃허브 Pages 를 켰는데 내 주소를 열면 404 가 나와.
저장소 첫 화면 캡처와 Settings → Pages 화면 캡처를 붙여 넣을게.
무엇이 잘못됐는지 찾아서, 내가 고칠 순서를 하나씩 알려 줘.

✅ 이렇게 보이면 성공

  • Pages 화면 위쪽에 「사이트가 열렸다」는 문장과 https://아이디.github.io/저장소이름/ 주소가 보인다(주소 옆에 Visit site 같은 단추가 있을 수 있어요).
  • 그 주소를 누르면 2단계에서 본 내 홈페이지가 열린다.
  • 저장소 위쪽 메뉴의 Actions 를 누르면, 배포 줄 앞의 노란 점이 돌다가 초록 체크(✓)로 바뀌어 있다 → 배포가 끝났다는 뜻입니다.

🧯 막히면

  • Settings 가 안 보인다 → 브라우저 창을 넓힙니다. 메뉴가 「…」 안에 숨어 있을 수 있습니다.
  • Branch 칸에 main 이 없다 → 아직 파일이 안 올라간 것입니다. 6단계로 돌아갑니다.
  • Actions 에 빨간 X 가 보인다 → 그 줄을 눌러 나온 화면을 캡처해 클로드에게: 「깃허브 Pages 배포가 실패했어. 이 화면에서 원인과 내가 고칠 순서를 알려 줘.」

화면 이름은 조금 다를 수 있어요. 막히면 화면을 캡처해 클로드에게 보여 주세요.

8단계 · 신청 버튼 연결하기 (구글 설문지 또는 카카오 오픈채팅)

왜 하나요? 홈페이지를 본 분이 신청 버튼을 누르면 내게 연락이 오게 합니다. 전화번호를 올리지 않아도 연락을 받을 수 있습니다. 둘 중 하나를 고릅니다.

설문지나 오픈채팅 링크를 이미 만들어 왔다면 가·나는 건너뜁니다(설문지라면 가의 7번 알림 켜기만 합니다). 2단계에서 그 링크를 이미 넣었다면 「링크 걸기」도 건너뛰고 ✅ 이렇게 보이면 성공으로 갑니다.

가. 구글 설문지 (추천)

  1. 크롬에서 구글에 로그인하고 forms.google.com 을 엽니다.
  2. 새 양식을 만드는 + 모양(빈 양식)을 누릅니다.
  3. 제목을 적습니다. 예: 「○○ 상담 신청」. 제목 아래 설명 칸에는 「모으는 것: 성함·연락처 / 쓰는 곳: 상담 신청 확인 / 보관: 상담이 끝나면 지웁니다」 한 줄을 적습니다.
  4. 질문을 3개만 만듭니다: 성함(단답형) · 연락받을 방법(단답형) · 궁금한 점(장문형).
  5. 오른쪽 위 단추(화면에 따라 「보내기」 또는 「게시」)를 누릅니다.
  6. 응답하는 분께 보낼 링크(🔗 모양)를 복사합니다.
  7. 위쪽 「응답」 탭에서 ⋮(점 세 개) → 「새 응답 이메일 알림 받기」를 켭니다. 그래야 신청이 오면 메일로 알 수 있습니다.

화면 이름은 조금 다를 수 있어요. 막히면 화면을 캡처해 클로드에게 보여 주세요.

설문지는 꼭 필요한 것만 묻습니다. 받은 연락처는 설명 칸에 적은 그 일에만 씁니다.

나. 카카오 오픈채팅

  1. 카카오톡에서 오픈채팅 만들기 메뉴로 갑니다.
  2. 1:1 채팅방을 고르고, 방 이름을 「○○ 상담」처럼 짓습니다.
  3. 만든 방의 링크 공유에서 주소를 복사합니다. 주소는 https://open.kakao.com/o/ 로 시작합니다.

메뉴 위치는 카카오톡 버전에 따라 다를 수 있습니다.

💬 클로드에게 이렇게 말하세요 (링크 걸기)

3기_작업\내홈페이지\index.html 의 신청 버튼 링크를 아래 주소로 바꿔 줘.
버튼을 누르면 새 탭으로 열리게 해 줘. 신청 버튼이 여러 개면 모두 바꿔 줘.
다른 곳은 고치지 마.
끝나면 바꾼 줄을 보여 주고, 버튼을 눌러 확인하는 방법을 알려 줘.
주소: (여기에 복사한 링크 붙여 넣기)

다시 올리기 — 이렇게 합니다

  1. 4단계 「비밀 검사」 문장을 다시 보내 「깨끗함」을 확인합니다. 고친 것이 링크 하나뿐이어도 합니다.
  2. 저장소 첫 화면에서 Add file → Upload files 를 누릅니다.
  3. 고친 index.html 하나만 끌어다 놓습니다.
  4. Commit changes 를 누릅니다. 같은 이름의 파일은 새 것으로 바뀝니다.

✅ 이렇게 보이면 성공

  • 내 컴퓨터에서 index.html 을 열고 신청 버튼을 누르면 설문지(또는 오픈채팅)가 새 탭으로 열린다.
  • 설문지 링크를 시크릿 창(Ctrl+Shift+N)에 붙여 넣어도 설문지가 보인다 → 다른 사람에게도 열린다는 뜻입니다.

🧯 막히면

  • 버튼을 누르니 「권한 필요」나 편집 화면이 나온다 → 링크 주소에 /edit 가 들어 있으면 내 편집용 주소입니다. 응답하는 분께 보낼 링크(보통 forms.gle 로 시작하거나 주소 안에 /viewform 이 들어 있음)로 바꿉니다.
  • 다시 올렸는데 버튼이 그대로다 → 몇 분 기다린 뒤 강력 새로고침(Ctrl+F5)합니다.

9단계 · 내 주소 확인하고 휴대폰으로도 열어 보기

왜 하나요? 명함을 받은 분은 대부분 휴대폰으로 엽니다. 휴대폰에서도 잘 보이는지 꼭 확인합니다.

이렇게 합니다

  1. PC에서 내 주소를 열고 신청 버튼을 눌러 봅니다.
  2. 주소창의 주소를 복사해 카카오톡 「나와의 채팅」에 보냅니다.
  3. 휴대폰에서 그 주소를 눌러 엽니다.
  4. 글자 크기, 줄 바꿈, 신청 버튼을 확인합니다.

💬 클로드에게 이렇게 말하세요 (휴대폰에서 어색할 때)

내 홈페이지를 휴대폰에서 열어 보니 [글자가 너무 작아 / 버튼이 화면 밖으로 나가 / 사진이 너무 커].
3기_작업\내홈페이지\index.html 을 휴대폰 화면에서도 보기 좋게 고쳐 줘.
PC 화면은 지금 모습 그대로 두고, 고친 뒤 무엇을 바꿨는지 쉬운 말로 알려 줘.

고친 뒤에는 8단계 「다시 올리기」와 같이 비밀 검사 → index.html 다시 올리기를 합니다.

✅ 이렇게 보이면 성공 — 오늘의 결과물

  • PC와 휴대폰에서 모두 https://아이디.github.io/저장소이름/ 이 열린다.
  • 신청 버튼을 누르면 설문지(또는 오픈채팅)가 열린다.
  • 이 주소를 명함·카카오톡 프로필에 적을 수 있다. 예: 「홈페이지 https://아이디.github.io/저장소이름/」

이 주소는 5주차 과제(6주차 시연 준비 네 줄)에 적고, 책이 승인되면 이 홈페이지에 책 소개를 더합니다. 6주차 시연회에서는 내 결과물로 보여 줍니다.

🧯 막히면

  • 휴대폰에서 404 가 나온다 → 주소를 끝의 / 까지 다 보냈는지, PC에서 연 주소와 한 글자도 다르지 않은지 봅니다. 손으로 치지 말고 PC에서 복사해 「나와의 채팅」으로 보냅니다. PC에서도 404 면 아래 「자주 막히는 곳」 1번을 따릅니다.
  • 휴대폰에 옛 화면이 보인다 → 카카오톡 안에서 열린 창을 닫고 다시 누릅니다. 그래도 같으면 오른쪽 위 메뉴의 「다른 브라우저로 열기」를 고릅니다(메뉴 이름은 조금 다를 수 있어요).

✋ 체크포인트 ③ — 기록 시간 전

휴대폰에서 내 주소가 열린 분은 ✋(손 들기)를 눌러 주세요. 안 된 분은 채팅에 막힌 단계 번호만 남겨 주세요(예: 「7」). 오늘 다 못 한 분은 과제 시간에 마저 하면 됩니다.

🆘 자주 막히는 곳

  1. 주소를 열면 404 가 나온다 → ① 몇 분 더 기다립니다. ② 저장소 첫 화면에 index.html 이 바로 보이는지(폴더 안에 들어가 있지 않은지) 봅니다. ③ 파일 이름이 정확히 소문자 index.html 인지 봅니다. ④ Settings → Pages 가 main / (root) 로 저장됐는지 봅니다.
  2. 고쳐서 올렸는데 옛 화면이 그대로다 → 반영까지 몇 분 걸릴 수 있습니다. PC는 Ctrl+F5, 휴대폰은 창을 닫았다가 다시 엽니다.
  3. 사진이나 꾸밈이 안 나온다 → 그림·스타일 파일을 같이 올렸는지 봅니다. 깃허브는 파일 이름의 대문자·소문자를 구별합니다(Photo.jpg 와 photo.jpg 는 다른 파일).
  4. 신청 버튼이 편집 화면이나 「권한 필요」로 간다 → /edit 주소를 넣은 것입니다. 응답하는 분께 보낼 링크로 바꿉니다.
  5. 한글이 이상한 글자로 깨진다 → 클로드에게 「index.html 을 UTF-8 로 저장하고 charset 설정을 확인해 줘」라고 말합니다.
  6. 열쇠나 비밀번호를 올려 버렸다 → ① 그 사이트에서 바로 지우거나 바꿉니다(이것이 진짜 해결). ② 그다음 저장소에서 파일을 지웁니다. 파일만 지우면 변경 기록에 남을 수 있어 ①이 먼저입니다. ③ 단톡방에 「비밀을 올렸어요」라고만 알리면 별님이 도와드립니다. 부끄러운 일이 아닙니다. 바로 바꾸는 것이 실력입니다.

과제가 아닙니다. 과제 3개를 끝내고 더 해 보고 싶은 분만 하세요. ①은 누구나, ②는 365blog 를 켜 본 분, ③·④는 심화입니다. 막히면 단톡방에 「더 배우기 ②의 3번」처럼 번호와 캡처를 올려 주세요.

더 배우기 ① 내 홈페이지에 블로그·영상 채널 모아 걸기

왜 하나요? 2주차에 글을 올린 내 블로그, 유튜브·틱톡 같은 영상 채널이 있다면 홈페이지 한 곳에 모아 걸어 둡니다. 명함에 주소 하나만 적어도 그 주소에서 내 블로그·채널·책으로 다 갈 수 있습니다. 여러 곳을 하나로 묶는 「통합」의 가장 쉬운 모습입니다.

이렇게 합니다

금고로 비유하면 — 다섯 가지

  4. 가려서 보여 주기(마스킹) = 화면이나 작업 기록(로그)에 ***** 로 보여 주기. 2주차 설정 칸이 별표로 가려진 것이 이것입니다.
  5. 저장 자리 따로 = 프로그램 폴더가 아니라 내 사용자 폴더 쪽에 저장하기. 프로그램을 남에게 줘도 열쇠는 따라가지 않습니다.
